# Kubernetes platform third-party manifest review

Review date: 2026-09-05

The pinned Phase 14 platform manifests have 76 Trivy high/critical findings under the CI-pinned
Trivy 0.74 Linux scanner. These are generated by
infrastructure components that require host or cluster-level access to perform their jobs.
`scripts/verify_platform_findings.sh` fails CI unless the exact finding-ID/count set remains unchanged.
This is not a blanket ignore: the application manifests must have zero high/critical findings, and any
chart upgrade or count change requires a new review.

## Accepted capabilities

| Finding | Component | Why it is required | Compensating controls |
| --- | --- | --- | --- |
| KSV-0005, KSV-0009, KSV-0014, KSV-0017, KSV-0024, KSV-0119, KSV-0120, KSV-0121 | Cilium | A CNI installs host networking programs, manages eBPF/kernel state, and exposes node-local health and peer ports. | Version and image digests are pinned; workloads run in `kube-system`; Cilium RBAC and changes are reviewed; the exact finding set is gated. |
| KSV-0010, KSV-0014, KSV-0017, KSV-0118 | NVIDIA device plugin | GPU discovery and MPS management require host device, process, and mount access on tainted GPU nodes. | Scheduled only on dedicated GPU nodes; no application AWS identity; chart version is pinned; GPU nodes are private. |
| KSV-0041, KSV-0114, KSV-0118 | External Secrets Operator | The controller reads/writes Kubernetes Secrets and maintains its admission webhook. | AWS access is IRSA-scoped; the operator has a dedicated namespace and service account; Secrets Manager and Kubernetes audit trails remain enabled. |
| KSV-0041, KSV-0046, KSV-0114 | KEDA | KEDA reads scaler authentication Secrets, manages autoscaled resources, and maintains its admission webhook. | Dedicated service account; no broad application cloud role; pinned chart; changes require a new manifest review. |
| KSV-0046, KSV-0056, KSV-0114, KSV-0118 | Kyverno | The policy engine's admission, cleanup, background, and migration controllers inspect and mutate cluster resources and webhooks. | Controllers have separate identities; policies are stored in Git; admission/audit events are observable; chart is pinned. |
| KSV-0056 | AWS Load Balancer Controller | The controller reconciles Services, Endpoints, EndpointSlices, Ingresses, and related AWS load balancers. | IRSA policy is scoped to controller operations; only the public ALB is internet-facing; chart and IAM policy changes are reviewed. |
| KSV-0109 | Cilium ConfigMap | Trivy classifies Cilium settings containing the word `secrets` as secret material, although these values are feature flags and namespace names. | No credentials or secret values are stored in the ConfigMap; actual secrets remain in Secrets Manager/Kubernetes Secrets. |
| KSV-0118 | Metrics Server and controller pods | Some upstream charts omit pod-level security context even when container-level restrictions are present. | Images/charts are pinned; namespaces and service accounts are dedicated; upgrades cannot change the accepted count unnoticed. |

The accepted set is 76 findings across 15 IDs. A change in either an ID or its count blocks the pull
request until this document and the verifier are deliberately updated after review.
